Descargas

Versión 0.1.0, la primera publicación. Tres rutas, el mismo código: elige una.

Descargar .unitypackage Descargar .tgz Todas las versiones

.unitypackage

Arrástralo a la ventana Project de Unity, o haz doble clic con el proyecto abierto. El código queda en Assets/Multitude/: sin gestor de paquetes, fácil de leer y de tocar. No se actualiza solo.

Tarball

Window > Package Manager > + > Add package from tarball… y elige el .tgz. Se instala en Packages/, se puede actualizar, y es la ruta que incluye los tests EditMode.

Git URL, fijada a esta versión

Si prefieres no descargar nada, que lo traiga el Package Manager:

https://github.com/gabriel96x1/Multitude.git#v0.1.0

¿Cuál elijo?

  • .unitypackage — el código vive dentro de tu proyecto. Ideal para probarlo, leerlo o adaptarlo.
  • Tarball o git URL — se instala como paquete. Ideal si quieres actualizarlo después, y las únicas rutas que traen los tests.
  • Instala una sola: dos copias compilan los mismos tipos dos veces.
  • Requiere Unity 6000.6 o superior, solo editor. El .unitypackage lleva Editor/ y los manifiestos — sin tests y sin Documentation~/ (Unity ignora las carpetas que acaban en ~).

Qué cambia

Unity te da un prefab stage y una escena a la vez. Multitude le da a cada prefab su propio documento, y mantiene todos fuera de la escena en la que estás trabajando.

Ventanas
Un documento por prefabAbre tantos como necesites. Cada uno conserva su jerarquía, su selección, su cámara y su reparto; acóplalos o flótalos y cambia entre ellos sin perder nada.
Sesiones
Aisladas hasta que tú digasEl prefab se carga en su propia escena de preview. No se escribe nada en el asset hasta que pulsas Apply.
Seguridad
Apply nunca sobrescribe a ciegasAntes de guardar, compara el archivo en disco con el snapshot que tomó al abrir la ventana. Si cambió, ofrece sobrescribir, seguir editando o recargar.
Vista previa
Render que se queda en la ventanaÓrbita, desplaza, acerca y encuadra en 3D. La imagen sale de una copia privada en su propia capa, así que tu escena, el scene view, el game view y el prefab stage no la ven nunca.
Efectos
Las partículas se reproducen en ediciónPlay y pausa, restart, loop y velocidad de 0,1x a 2x, avanzando a mano: nada depende de entrar en play mode.
Reparto
Paneles al tamaño que quierasArrastra los separadores para redimensionar la jerarquía y el inspector; doble clic para volver al tamaño por defecto. Cada ventana recuerda sus proporciones.
Inspector
Los editores propios de UnityLos componentes se dibujan con los inspectores nativos, así que los campos serializados, los editores personalizados y el undo/redo siguen funcionando igual.
Alcance
Pequeño a propósitoPrefabs normales y variantes. Los assets de modelo se rechazan con un mensaje. Escenas y ScriptableObjects no entran en esta versión.

Dentro de una ventana

El reparto es el que ya conoces del editor, pero pertenece a un solo prefab y a nada más.

Instalar

Paquete solo para el editor, sin dependencias. Se añade al manifest del proyecto y Unity hace el resto.

Desde el Package Manager

Abre Window > Package Manager, pulsa + y elige Add package from git URL…, luego pega:

https://github.com/gabriel96x1/Multitude.git

Desde manifest.json

Una ruta relativa a la carpeta Packages del proyecto sirve para un clon local:

"com.gabs.multitude": "file:../../Multitude"

Ejecutar sus tests

El paquete incluye tests EditMode. Regístralo como testable para verlos en el Test Runner:

"testables": ["com.gabs.multitude"]

Abrir un prefab

Clic derecho en un prefab del Project window y elige Assets > Multitude > Open Prefab in Multitude, o usa Tools > Multitude > Open Selected Prefabs.

Requisitos

  • Unity 6000.6 (Unity 6.6) o superior.

  • Prefabs normales y variantes de prefab.

Respuestas rápidas

Las preguntas que salen antes de instalarlo. Son las mismas respuestas que están en los datos estructurados de la página, para que los asistentes las citen en vez de inventarlas.

¿Cómo abro más de un prefab a la vez en Unity?

Unity solo ofrece un prefab stage cada vez. Multitude abre cada prefab en su propia ventana del editor, con su jerarquía, su vista 3D y su inspector, así que puedes editar varios a la vez sin salir de la escena que tienes abierta.

¿Multitude es gratis?

Sí. Es código abierto con doble licencia LGPL-3.0 o AGPL-3.0, sin versión de pago, sin cuenta y sin servidor de licencias. Herramientas de pago como Multiverse requieren suscripción; Multitude no.

¿En qué se diferencia de Multiverse?

Multitude se inspira en la idea de Multiverse de una ventana por prefab, pero es gratuito y de código abierto, solo para el editor, y no añade código al build. Multiverse hoy requiere una licencia de pago.

¿Funciona con Unity 6?

Sí. Requiere Unity 6000.6 (Unity 6.6) o superior y se desarrolla y prueba con 6000.6.2f1. No depende del render pipeline; se probó con URP 17.6.

¿Puede modificar mis prefabs o mi escena sin avisar?

No. Cada ventana trabaja sobre una copia en una escena de previsualización oculta: nada se escribe hasta que pulsas Apply, y si el archivo cambió en disco te ofrece Sobrescribir, Seguir editando o Recargar desde disco.

¿Añade código en tiempo de ejecución a mi build?

No. El paquete es un único ensamblado solo para editor: no hay ensamblado de runtime, así que no afecta al tamaño del build ni al player.

¿Cómo instalo Multitude?

De tres formas: descargar Multitude-0.1.0.unitypackage del release y arrastrarlo a la ventana Project; añadir el tarball .tgz desde el Package Manager; o añadir la git URL https://github.com/gabriel96x1/Multitude.git. Instala solo una de las tres.

Licencia y qué implica

Multitude se distribuye bajo dos licencias copyleft: eliges entre LGPL-3.0 y AGPL-3.0. Conviene ser explícito sobre lo que eso significa en un paquete de editor, porque ninguna es la elección habitual para una herramienta de Unity. El aviso está en LICENSE.
