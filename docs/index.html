Skip the download and let the Package Manager pull it:

Which one?

  • .unitypackage — the code lives inside your project. Best for trying it, reading it or patching it for yourself.
  • Tarball or git URL — installed as a package. Best if you want to update it later, and the only routes that carry the tests.
  • Install one of them: two copies compile the same types twice.
  • Needs Unity 6000.6 or newer, editor only. The .unitypackage ships Editor/ and the manifests only — no tests, and no Documentation~/ (Unity ignores folders ending in ~).

What it changes

Unity gives you one prefab stage and one scene at a time. Multitude gives each prefab its own document, and keeps every one of them out of your working scene.

Windows
One document per prefabOpen as many as you need. Each keeps its own hierarchy, selection, camera and layout; dock or float them and switch without losing anything.
Sessions
Isolated until you say soThe prefab loads into its own preview scene. Nothing is written to the asset until you press Apply.
Safety
Apply never overwrites blindBefore saving, Multitude compares the file on disk with the snapshot taken when the window opened. If it changed, it offers overwrite, keep editing or reload.
Preview
Render that stays inside the windowOrbit, pan, zoom and frame in 3D. The picture comes from a private copy on its own layer, so your scene, scene view, game view and prefab stage never see it.
Effects
Particles play in edit modePlay and pause, restart, loop and a 0.1x–2x speed slider, driven by hand so nothing depends on entering play mode.
Layout
Panels the size you wantDrag the separators to resize the hierarchy and the inspector; double click to reset. Each window remembers its own proportions.
Inspector
Unity's own editorsComponents draw with the built in inspectors, so serialized fields, custom editors, undo and redo keep working as usual.
Scope
Deliberately smallOrdinary prefabs and variants. Model assets are rejected with a message. Scenes and ScriptableObjects are not part of this version.

Inside a window

The layout is the same one you know from the editor, but it belongs to a single prefab and nothing else.

Install

Editor only package, no dependencies. Add it to the project's manifest and Unity does the rest.

From the Package Manager

Open Window > Package Manager, press + and choose Add package from git URL…, then paste:

https://github.com/gabriel96x1/Multitude.git

From manifest.json

A path relative to the project's Packages folder works for a local clone:

"com.gabs.multitude": "file:../../Multitude"

Run its tests

The package ships EditMode tests. Register it as testable to see them in the Test Runner:

"testables": ["com.gabs.multitude"]

Open a prefab

Right click a prefab in the Project window and choose Assets > Multitude > Open Prefab in Multitude, or use Tools > Multitude > Open Selected Prefabs.

Requirements

  • Unity 6000.6 (Unity 6.6) or newer.
  • Editor only: the package adds no runtime code to your build.
  • Tested with URP 17.6; the code has no pipeline dependency.
  • Ordinary prefabs and prefab variants.

License, and what it means

Multitude is released under two copyleft licenses: you choose between LGPL-3.0 and AGPL-3.0. It is worth being explicit about what that means for an editor package, because neither is the usual choice for a Unity tool. The notice is in LICENSE.

Two licenses
LGPL-3.0 or AGPL-3.0, you chooseMultitude is dual licensed: pick, per copy or distribution, whichever of the two fits your case. The notice is in LICENSE and the full texts in licenses/.
LGPL-3.0
For closed or sold productsYou can ship Multitude inside a closed product as long as the library itself — and any modification you make to it — stays under the LGPL and the user can replace it. This is the option that fits a commercial Unity tool.
AGPL-3.0
Strong copyleft, network includedOffering the tool as a service also counts as distribution, so any modified version has to publish its source under the same license.
Common ground
Neither is permissiveIn both cases modifications to the library stay open: there is no MIT-style "do what you want" path. Using it privately, or inside a project you do not distribute, forces nothing.
